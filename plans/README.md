## Wave 3 — larger / design work (needs a decision or a design plan, not a blind fix)

Do NOT hand these to a weak executor as-is; they need design choices first.

- **PERF-01 — Move per-message DB writes / media download / mark-read off the
  whatsmeow dispatch goroutine** (`event_message_handler.go:45,51,54`). M, MED
  risk. This is the serialization behind the "send timeouts under load" class of
  bug (upstream #732). Needs a per-chat serialized worker queue (not a naive
  `go`), preserving edit/reaction ordering. Write as a design plan.
- **PERF-04/08 — Cache Chatwoot contact/conversation IDs** to cut 2+ REST
  round-trips per forwarded message (`webhook_forward.go:641,648`); then narrow
  the per-contact mutex to the cache-miss create. M, MED risk (stale-cache /
  merged-conversation handling; TTL + 404 invalidation).
- **Chatwoot boundary / fork-drift cluster** (DEBT-01/02/03/06/07, DIR-06). L.
  The Chatwoot layer is woven into 10+ upstream-owned files (`webhook_forward.go`
  1168 lines, `sqlite_repository.go` 2113, `usecase/send.go` 1830,
  `config/settings.go`, `ui/rest/chatwoot.go` with business logic), guaranteeing
  merge conflicts on every upstream pull. Write as a **design spike**: define a
  `ChatwootSink` interface + one injection point in the event handlers, and a
  `config/chatwoot.go` var block, then measure conflict-surface reduction. Do the
  characterization tests (below) first as a safety net.
- **Test coverage** (`usecase/` 3.6%, `ui/rest/` 6.5%, event handlers + retry
  worker 0%). Highest-value S starters: table tests for `NormalizeJIDFromLID`
  (`jid_utils.go:12`, 15% on a routing-critical primitive) and a
  `call_validation_test.go` (only validator with no test). Then the Chatwoot
  webhook handler and forward-retry worker (M each). `go test -race` already
  passes, so a race gate is viable.
- **Direction options** (product, your call): per-device Chatwoot inboxes
  (DIR-01, L); durable retry for inbound agent replies (DIR-03, M, reuses
  existing retry infra); dead-letter + backlog visibility on the retry queue
  (DIR-04, M); relay agent reactions back to WhatsApp (DIR-02, M spike).

## How to run these

Under the `/improve` skill the advisor does not hand-edit source. To apply a
plan: run `/improve execute plans/NNN-*.md` — a dispatched executor implements it
in an isolated git worktree, then the advisor reviews the diff (re-runs done
criteria, checks scope) and reports a verdict. Nothing is committed to your
branch without you applying it. Alternatively, hand a plan file to any executor
as a fully self-contained spec.
